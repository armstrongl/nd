## Agent-agnostic docs: cmd/ source strings and full file scope

### Objective

Expand and correct seed task `vkerqg` ("Update docs to be agent-agnostic",
`tasks/cli/vkerqg-docs-agent-agnostic.md`). This task supersedes the seed's
scope and method; do `vkerqg` and this task together as one unit (this task
depends on `vkerqg`).

Two corrections to the seed:

1. **The seed's counts are wrong.** Seed claims "~150 occurrences across 52
   files + 3 in README". Actual verified totals (run from repo root):
   `grep -rIin "claude code" docs/guide docs/reference README.md | wc -l` = **66
   lines across 19 files**. The seed's `.claude/` numbers are similarly inflated.

2. **The seed's premise is partly wrong.** The seed says to replace *all*
   "Claude Code" references. Most of the 66 lines are **legitimate** content
   that must stay: nd genuinely supports Claude Code (and Copilot CLI), so the
   guide deliberately uses per-agent comparison tables, "Supported agents"
   lists, and "Claude Code vs Copilot CLI" prose. Deleting those would make the
   docs *less* accurate. The real goal is narrower:

   > Remove phrasing that implies nd is **Claude-Code-only** or treats Claude
   > Code as the sole/implied agent. Keep every reference that names Claude Code
   > as *one of several* supported agents inside explicit per-agent content.

The seed also missed the actual root cause for `docs/reference/`: those pages
are generated by `cmd/gendocs` from Cobra command definitions in `cmd/`.
Editing `docs/reference/*.md` by hand is futile — `go run ./cmd/gendocs/`
overwrites them. The source strings live in `cmd/export.go`.

Caveat to weigh while editing `cmd/export.go`: the export feature genuinely
produces a Claude Code plugin (it writes `.claude-plugin/plugin.json`, see
`cmd/export.go:385`). "Export assets as a Claude Code plugin" is arguably
*accurate*, not just branding. Recommended resolution: keep it factually
correct but neutral, e.g. Short = "Export assets into Claude Code plugin
format" / Long noting the format is Claude Code's plugin format and is the
distribution path regardless of which agent authored the assets. Do not assert
nd only targets Claude Code.

### Background: terms used here

- **Seed task `vkerqg`**: the prerequisite docs task this one corrects;
  file `tasks/cli/vkerqg-docs-agent-agnostic.md`. Its GitHub issue is
  https://GitHub.com/armstrongl/nd/issues/77.
- **`gendocs`**: `cmd/gendocs/main.go`, a `package main` binary. Run with
  `go run ./cmd/gendocs/` (default output dir `docs/reference`). It calls
  `cmd.NewRootCmd` and uses `spf13/cobra/doc.GenMarkdownCustom` to emit one
  `.md` per command from each command's `Use`/`Short`/`Long`/`Example` and
  annotations. Every string in `docs/reference/` originates in `cmd/`.
- **legitimate agent ID `claude-code`**: the kebab-case identifier nd uses for
  the Claude Code agent (the value of `--agent` and of `default_agent` in
  config). These are functional identifiers, not branding — leave intact.
