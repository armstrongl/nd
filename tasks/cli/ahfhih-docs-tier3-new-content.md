## Docs tier 3: new content guides

### Objective

Create or extend documentation for nine real, currently-undocumented `nd`
behaviors found in the better-docs audit (2026-04-05). A user reading the
existing `docs/guide/` set today has no way to discover the TUI, the
export/marketplace workflow, team-scoped config, several CLI flags, the
auto-snapshot safety net, state-file locking, ghost-deployment pruning, the
`nd sync` output labels, or the backup retention policy. This task adds that
content and resolves the "Napoleon Dynamite" branding question.

Scope correction (verified 2026-05-17 against the repo — do not re-investigate):

- The docs directory is `docs/guide/` (singular), NOT `docs/guides/`. Create
  every new guide under `docs/guide/`.
- The style rules referenced by the original task as `.claude/CLAUDE.md` do
  NOT exist. The authoritative style rules are in
  `.github/copilot-instructions.md:150-155` (sentence-case headings, base-verb
  forms, no forbidden words `simple/simply/easy/easily/just/obviously/straightforward`,
  ` ```shell ` fences). They are mechanically enforced by `scripts/lint-docs.sh`
  and `.rumdl.toml` (`[MD063] style = "sentence-case"`).
- `docs/reference/*.md` is auto-generated by `go run ./cmd/gendocs/` from Cobra
  definitions. Do NOT hand-edit reference pages — change the Cobra command in
  `cmd/` and regenerate. (CONTRIBUTING.md:70)
- T3-14 and T3-18 below are already satisfied in the codebase; they are kept
  as verification steps, not new work. Sibling task `oema5w`
  (`tasks/cli/oema5w-expand-docs-undocumented-cli.md`, depends on this task)
  tracks the same reconciliation — coordinate, do not duplicate.

### Tasks

- [ ] **T3-8: Write a TUI guide.** Create `docs/guide/tui.md`. The bare `nd`
  command launches the TUI when stdin is a terminal and no `--verbose/--quiet/--json`
  flag conflicts: `cmd/root.go:44-50` (`RunE` → `tui.Run(app)`). Document
  navigation, key bindings, the screens, and scope switching using the actual
  screen implementations in `internal/tui/` (entry: `internal/tui/tui.go`;
  screens: `main_menu.go`, `browse.go`, `deploy.go`, `remove.go`, `profile.go`,
  `snapshot.go`, `source.go`, `settings.go`, `status.go`, `doctor.go`, `pin.go`;
  key bindings: `internal/tui/helpbar.go`; scope: `internal/tui/scope.go`).
  Mirror an existing guide's structure (e.g. `docs/guide/user-guide.md`).
- [ ] **T3-9: Write an export/plugin workflow guide.** Create
  `docs/guide/export-plugin-workflow.md`. Document the two phases: (1)
  `nd export` builds a plugin (`cmd/export.go:20-200`, flags at
  `cmd/export.go:159-168`: `--name --version --author --email --license --overwrite`,
  plus `--assets --output`); (2) `nd export marketplace` builds a marketplace
  from exported plugins (`cmd/export.go:203-305`, flags `--name --description
  --owner --plugins --output`, defined `cmd/export.go:299-303`). Use the two
  worked examples already in the Cobra `Example` fields (`cmd/export.go:42-45`
  and `cmd/export.go:220-221`). Mirror `docs/guide/asset-types/plugins.md`.
- [ ] **T3-10: Write a team/project-scoped config guide.** Create
  `docs/guide/team-config.md`. Cover: relative vs absolute symlinks
  (`--relative`/`--absolute`, `cmd/deploy.go:291-292`; default behavior
  documented at `docs/guide/getting-started.md:154`), git sources for team
  sharing including SSH/`git@`/`ssh://` URLs (`internal/sourcemanager/git.go:11-44`),
  and project-scoped vs user-scoped config. Build on
  `docs/guide/configuration.md` and `docs/guide/creating-sources.md`; link the
  new guide from `docs/guide/user-guide.md`.
- [ ] **T3-11: Document missing CLI flags in guides.** Add usage examples and
  prose for: `--absolute` (`cmd/deploy.go:292`), `--source` (filter by source
  ID, `cmd/list.go:147`), `--pattern` (filter by name pattern,
  `cmd/list.go:148`), `--alias` (`nd source add --alias`, `cmd/source.go:122`),
  and SSH URL support (`internal/sourcemanager/git.go:11-44`). These appear in
  zero `docs/guide/*.md` files today. Add them to `docs/guide/user-guide.md`
  (it already has a "Manage sources" and "Deploy assets" section) and/or
  `docs/guide/getting-started.md`. Do NOT edit `docs/reference/` — those pages
  already list the flags from Cobra and are regenerated.
- [ ] **T3-12: Document auto-snapshot on bulk deploy/remove.** Explain that
  bulk deploy and bulk remove call `Engine.autoSnapshot` first
  (`internal/deploy/deploy.go:23-26` `SnapshotSaver` interface;
  `:88-96` `SetSnapshotSaver`/`autoSnapshot`; tests
  `internal/deploy/deploy_test.go:918` and `:958`). It is best-effort: a
  snapshot failure does NOT block the operation (`deploy.go:91-96`, FR-029a).
  Document how to restore via `nd snapshot list` / `nd snapshot restore`. Add
  to `docs/guide/profiles-and-snapshots.md` and/or
  `docs/guide/troubleshooting.md`.
- [ ] **T3-13: Document state-file locking and concurrent-process errors.**
  Explain `internal/state/lock.go`: `FileLock` is an advisory lock on
  `deployments.yaml` (`lock.go:12-22`); on contention it returns
  `*nd.LockError` (`lock.go:53`); a lock older than 60s
  (`staleLockThreshold`, `lock.go:25-26`) is treated as stale, removed, and
  acquisition is retried once (`lock.go:30-31`, `breakAndRetry` `:72-89`).
  Document the user-visible error and that stale locks self-heal after 60s.
  Add a section to `docs/guide/troubleshooting.md`.
- [ ] **T3-14 (verify-only — already satisfied).** Confirm
  `agents[].source_alias` is present in the config key table at

- [ ] **T3-15: Document ghost-deployment pruning.** Explain the silent
  self-healing in `internal/deploy/health.go`: `Prune()` removes deployment
  records for the active agent whose symlinks no longer exist on disk
  (`health.go:107-111`), `PruneAll()` does it for all agents (`:114-118`),
  `pruneFiltered` skips records whose symlink is gone ENOENT
  (`:121-146`, "ghost: skip this record"). This runs implicitly during
  deploy/status. Add to `docs/guide/how-nd-works.md` and/or
  `docs/guide/troubleshooting.md`.
- [ ] **T3-16: Explain `nd sync` "Repaired" vs "Removed" output.** The
  `SyncResult` struct (`internal/deploy/health.go:19-21`) has `Repaired` and

  Add to `docs/guide/how-nd-works.md` or `docs/guide/troubleshooting.md`.

### Acceptance criteria

- New guides exist at `docs/guide/tui.md`, `docs/guide/export-plugin-workflow.md`,
  and `docs/guide/team-config.md`, and each is linked from
  `docs/guide/user-guide.md` (or the guide it logically belongs under) so it
  is reachable from navigation.
- `--absolute`, `--source`, `--pattern`, `--alias`, and SSH/`git@`/`ssh://`
  URL support are each explained with a runnable example in at least one
  `docs/guide/*.md` file.
- Auto-snapshot-before-bulk, state-file locking + stale-lock recovery,
  ghost-deployment pruning, the `nd sync` Repaired/Removed labels, and the
  5-backup retention policy each have a documented section in an existing
  guide.
- `bash scripts/lint-docs.sh <changed guide files>` reports zero `error`-level
  findings.
- `agents[].source_alias` row is present and accurate in
  `docs/guide/configuration.md` (T3-14 verified).
- `nd profile create --help` shows a non-empty Example (T3-18 verified); any

  `git diff --exit-code docs/reference/` clean after `go run ./cmd/gendocs/`.

  task worklog (and applied via `cmd/root.go:23` + regen if changed).
